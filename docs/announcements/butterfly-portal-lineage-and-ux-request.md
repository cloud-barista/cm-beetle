# [요청] Butterfly (Portal) 마이그레이션 모델 UX 개선 요청

## 1. 요청 사항

1. **모델 편집 UI 폼 제공 및 일괄 수정 고려**: JSON 직접 편집을 지양하고 화면 입력 폼을 제공하며, 계획 수립은 `Planning Model` 단계로 분리 (다수 노드를 위한 규칙/패턴 기반 일괄 수정 고려)
2. **배포 인프라 출처 표기 및 리포트 연계**: Beetle 배포 인프라 및 Node의 Label 정보를 조회하여 출처 정보 표기 및 마이그레이션 리포트 탭 렌더링

---

## 2. 요청 이유

과제 1단계에서 임시로 제공되던 포털의 모델 JSON 직접 수정 방식으로 인해 `specId` 중복 노출 등 사용자 혼란이 발생했습니다. 모델 구조체는 마이그레이션에 필수적인 순수 기술 스펙이므로, 백엔드 모델 분할(User/System) 대신 **포털 UI 폼 기반 편집으로 전환**하고, **배포 인프라의 출처 추적성**을 화면에 제공하기 위함입니다.

---

## 3. 구현 방안 (안)

### 1) UI 폼 제공 및 계획 단계 분리

- JSON 전문 직접 편집을 가급적 지양하고 필요한 필드만 입력 폼으로 제공하며, `specId` 등 내부 식별자는 UI에서 은닉합니다.
- 소스 모델은 원천으로써 수정 불가(Read-Only)로 두고, OS 변경(CentOS to Ubuntu) 등 사용자 계획은 `Planning Model` 생성 화면으로 분리합니다.
- **규칙/패턴 기반 일괄 수정 고려 (권장)**: 다수 노드가 존재하는 대규모 마이그레이션 환경을 위해, 개별 노드 수정 외에도 특정 조건(예: OS가 CentOS인 모든 노드, 이름 패턴이 `web-*`인 노드 등)에 따라 설정을 일괄 적용할 수 있는 규칙/패턴 기반 편집 UI 지원을 권장합니다.

### 2) 배포 인프라 출처 표기 및 리포트 연계

- Beetle 배포 인프라 및 Node의 Label 정보를 조회하여 화면에 표기합니다:
  - **인프라 헤더 Label**: `cm-target-model-id`, `cm-source-model-id`, `cm-migrated-at`(배포 완료 일시)
  - **Node Label**: `cm-source-machine-ids`(원천 머신 매핑)
- Beetle이 생성하는 마이그레이션 리포트(Markdown)를 포털 리포트 탭에서 렌더링합니다.

---

## 4. 추후 고려 사항

1. **ID 기반 경량 API 호출 연계**:
   - 향후 Beetle의 모델 ID 기반 호출 API 지원이 완료되면, 거대 JSON 전문 대신 Damselfly 모델 ID(`planningModelId`, `targetModelId`)만 전달하는 호출 방식으로 전환을 검토합니다.
2. **마이그레이션 현황 도식화**:
   - 소스 모델 to 계획 모델 to 타겟 모델 파이프라인 흐름 가시화를 검토합니다.
   - 노드 수가 많아질 경우 개별 노드 간의 연결선은 화면 복잡도를 높일 수 있으므로, 그룹/역할 단위 요약 등 대규모 환경에 적합한 가시화 방식을 추후 협의합니다.

---

## 5. 기대 효과

1. **사용자 경험 개선**: JSON 직접 수정에 따른 오입력 문제를 원천 해결하고, 다수 노드에 대한 규칙 기반 일괄 편집 편의성을 확보합니다.
2. **배포 인프라 추적성 확보**: 배포된 인프라가 어떤 모델로부터 파생되었는지 화면에서 즉각 파악할 수 있습니다.
